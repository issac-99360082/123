# 安全模型與殘餘風險

已修正並附回歸測試的項目見 `tests/test_security_regressions.py` 與
`tests/test_fault_injection.py`。**本文件記錄「已知但尚未完全消除」的風險** ——
被修掉的問題有測試守著,沒被修掉的必須寫下來,否則下一個人會以為它不存在。

## 威脅模型

核心特性決定風險輪廓:**它接受陌生人提供的 URL,用我們的伺服器去抓取。**
這使它天生是 SSRF 代理候選者,也是運算資源的免費出租對象。

| 來源 | 能做什麼 |
|---|---|
| 匿名使用者 | 註冊、耗用免費額度、探測公開端點 |
| 已註冊使用者 | 指定任意 URL、任意擷取規則、任意 webhook 目的地 |
| 被監控的網站 | 惡意/超大/極慢內容、重導向、無限重導向 |
| 客戶的 webhook 端點 | 慢速回應佔用送信執行緒 |

## 殘餘風險

### R1. DNS rebinding(中)—— **上線前必須處理**

`validate_target_url()` 解析主機名並確認結果都是公開位址,
但**實際連線時 httpx 會再解析一次**。控制權威 DNS 且 TTL 極短者可在兩次解析之間
把記錄改成 `169.254.169.254`。

已降低:每一次重導向都會重新驗證,最常見的 SSRF 路徑已封閉。

**真正的緩解在網路層**:防火牆封鎖 worker 對 RFC1918 與 `169.254.0.0/16` 的出站;
雲端強制 IMDSv2 且 hop limit = 1;或讓出站抓取走只允許公開網段的 egress proxy。
**至少要做到第一項。** 應用層檢查是縱深防禦,不是唯一防線。

### R1b. 反向代理設定錯誤會使所有 per-IP 控制失效(中)

`TRUST_PROXY_HEADERS` 預設 `false`。設為 `true` 時**前方必須有會覆寫
`X-Forwarded-For` 的代理**,否則使用者可自選 rate-limit 分桶
(實測:標頭被無條件信任時,單一攻擊者在限制為 5 下建立 **20/20** 個帳號)。
**Caddy 與 nginx 的預設是附加而非覆寫。**

### R2. 帳號列舉(中)—— 已縮小,未關閉

註冊錯誤訊息已不揭露信箱是否已註冊,但**狀態碼仍不同**(400 vs 201)。
完全關閉需改為 email 驗證流程(兩種情況都回相同的 202),需要 SMTP。

### R3. 沒有 email 驗證(中)—— 已緩解,未消除

註冊限每 IP 每小時 5 個,但擁有大量 IP 者仍可批量開免費帳號。
上線前建議至少加一項:email 驗證、CAPTCHA,或免費方案要求綁卡(Stripe 可只驗證不扣款)。

**免費方案成本上限**:每帳號 3 監控 × 每小時 ≈ 2,160 次檢查/月。
以單機 20 checks/s 計,約需 2 萬個濫用帳號才吃滿一台機器。

### R4. 速率限制是單一程序內的記憶體狀態(中)

`TokenBucket` 與 `SlidingWindow` 存在程序記憶體中,因此 N 個 API 副本時實際限制變成 N 倍,
且**API 重啟會清空所有計數,包含登入鎖定**。單一 API 程序下行為正確;水平擴充須換 Redis。

### R5. 使用者的 `request_headers` 以明文存放(中)

監控自有 API 時填入的 `Authorization` 等憑證明文存於 `monitors.request_headers`。
API 回應不會回傳,但**資料庫備份含有這些憑證**。
緩解:加密該欄位(需金鑰管理),或明確告知使用者只放唯讀憑證 —— **目前採後者**,已寫入 `privacy.md`。

### R6. 內部位址在錯誤訊息中被回報(低)

`Target 10.1.2.3 is not a public address.` 會告知某位址被判定為私有。
判定純依 IP 區段(不代表該主機存在),幫助有限,但仍是不必要的資訊。

### R7. 單點故障(中)

單一 worker 擁有整個排程。它掛掉時**檢查會靜默停止**,API 仍正常、`/healthz` 仍回 200。
**緩解:對 `/metrics` 的 `oldest_due_monitor_age_seconds` 設外部告警。**

### R8. 檢查與送信共用同一個 tick 與執行緒池(低)

送信已併發化,但仍與檢查在同一 tick 內序列執行;極端負載下大量送信會延後下一輪檢查。
訊號:`monitors_due` 與 `deliveries_pending` 同時上升。

### R9. 無 circuit breaker(低)

對持續失敗的目標只有指數退避與連續失敗自動暫停(20 次),沒有真正的斷路器。

## 已實際攻擊過並確認擋住

| 防護 | 驗證方式 |
|---|---|
| 重導向 SSRF | 公開主機 302 → 127.0.0.1,擋下(`blocked_target`) |
| 無限重導向 | 重導向迴圈,擋下(`too_many_redirects`) |
| 慢速 trickle(slow-loris) | 每秒 15 bytes,12 秒總時限中止(`deadline_exceeded`) |
| gzip 解壓縮炸彈 | 305 KB → 314 MB,串流在 2 MB 截斷,記憶體有界 |
| ReDoS | 6 種病態模式,最壞 2.0s(修正前無上限) |
| 跨帳號資料存取 | 讀/改/刪他人監控全部 404,列表為空 |
| Stripe 簽章偽造 | 拒絕且不留下事件紀錄 |
| Stripe 重放與亂序 | 重複 id 忽略;過期事件不會還原已取消的方案 |
| 併發重複認領 | 4 worker × 40 監控,零重複 |
| X-Forwarded-For 偽造 | 預設不信任,20/20 → 0/20 |
| 鎖定被用於阻斷合法使用者 | 12 個攻擊來源後擁有者仍可登入 |
| 暫時空白頁假警報 | 4 次 → 0 次,而真正變空仍會回報 |
| 帳號刪除與匯出 | 實際級聯刪除 monitors/checks/change_events/api_keys |
| 資料庫中斷 | 降級為 503 + `Retry-After`,不外洩內部細節 |
